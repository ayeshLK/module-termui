In about five minutes you will run a small interactive program in your terminal: a counter you change with
the `+` and `-` keys. It is the smallest program that shows the whole shape of a termui application. You
need Ballerina 2201.14 and JDK 25, on macOS or Linux.

## Create a package

```sh
bal new counter
cd counter
```

`bal new` gives you a `main.bal` with a hello-world `main`. Delete everything in it: you will build the
program up in four stages, and `bal build` compiles after each one. There is nothing to add to
`Ballerina.toml`: the first `bal build` fetches the latest release from
[Ballerina Central](https://central.ballerina.io/ayesha/termui/1.0.0) and records its version in
`Dependencies.toml`.

## Write the program

Each stage says whether its code replaces something you already have or is added to it. Add imports to the
ones already at the top of `main.bal`, in alphabetical order. If you add an import too early, the compiler
reports an unused module prefix, so each stage adds only the imports it uses.

### 1. A skeleton

Add these imports:

```ballerina
import ayesha/termui;
import ayesha/termui.text;
```

Add this class at the end of the file. **The program is a class.** `*termui:Program` says so: the class has
an `update` and a `view`, and its state, `count`, is an ordinary field. Both functions are empty for now.

```ballerina
class Counter {
    *termui:Program;

    int count = 0;

    public function update(termui:Message message) returns termui:Command? {
        return ();
    }

    public function view() returns text:Span[][] {
        return [];
    }
}
```

### 2. Update

**`update` handles messages.** The runtime calls it for every message: a key press, a resize, a timer
tick. Anything it does not recognise, it ignores by returning `()`. Add this import:

```ballerina
import ayesha/termui.term;
```

Inside `Counter`, replace the empty `update` with this one:

```ballerina
    public function update(termui:Message message) returns termui:Command? {
        if message is term:KeyEvent {
            if message.key == "+" {
                self.count += 1;
            } else if message.key == "-" {
                self.count -= 1;
            } else if message.key == "q" {
                return termui:quit();
            }
        }
        return ();
    }
```

### 3. View

**`view` describes the screen.** It returns lines, each a list of styled spans. It does not draw anything:
the runtime calls it after handling messages and writes only what changed. Inside `Counter`, replace the
empty `view` with this one:

```ballerina
    public function view() returns text:Span[][] {
        return [
            [{text: "count: " + self.count.toString(), style: {bold: true}}],
            [{text: "+ and - change it, q quits", style: {dim: true}}]
        ];
    }
```

### 4. Main

**`main` connects the program to a terminal.** `term:detectEnvironment()` looks at what the process is
attached to, and `ui.run` runs the loop until the program returns `quit()`. Add this at the end of the file:

```ballerina
public function main() returns error? {
    termui:Interface ui = new (term:detectEnvironment());
    check ui.run(new Counter());
}
```

## Run it

```sh
bal run
```

Press `+` and `-` and watch the count change, then `q` to quit.

## What you wrote

- **`update` changes state.** It receives a message, changes `self`, and may return a command that tells the
  runtime what to do next, here `quit()`.
- **`view` describes the screen** from that state. After each change the runtime compares the new lines
  with the last ones and writes only the cells that differ.
- **Running it is a few lines.** `ui.run` repeats update and view until the program quits.
  [The update and view loop](../../concepts/the-loop/) follows one key press through all three.

## Change one thing

Make `+` add ten: change `self.count += 1;` to `self.count += 10;`, save, and run it again.
