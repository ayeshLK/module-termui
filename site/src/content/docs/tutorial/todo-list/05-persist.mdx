The list is gone as soon as the program exits. In this step it reads its items from a file when it starts and
writes them when you quit. None of it touches the `TodoList` class: the program does not know where its items
come from.

## What changes

- Two helper functions, `loadItems` and `saveItems`, read and write a JSON file.
- `main` loads the items, runs the program until you quit, and saves them.

## The program

Start from step 4's program. You make two changes, and `bal build` compiles after each.

### 1. Load and save

The list lives in a file next to where you run the program. Reading and writing it is ordinary Ballerina, using
two libraries that are part of Ballerina and need no download. Add these imports, in alphabetical order:

```ballerina
import ballerina/file;
import ballerina/io;
```

Add this between the `TodoList` class and `main`:

```ballerina
const string FILE_NAME = "todos.json";

function loadItems(string path = FILE_NAME) returns Item[]|error {
    if !check file:test(path, file:EXISTS) {
        return [];
    }
    json content = check io:fileReadJson(path);
    return content.cloneWithType();
}

function saveItems(Item[] items, string path = FILE_NAME) returns error? {
    check io:fileWriteJson(path, items.toJson());
}
```

### 2. Main

`main` loads the items, runs the program until you quit, and saves them. Replace `main` with this one:

```ballerina
public function main() returns error? {
    TodoList list = new (check loadItems());
    termui:Interface ui = new (term:detectEnvironment());
    check ui.run(list);
    check saveItems(list.items);
}
```

Run it, add a few items, quit, and run it again:

```sh
bal run
```

## What you built

- **A program is a class** with `update` and `view`. [The update and view loop](../../../concepts/the-loop/)
  follows one message through it.
- **The screen is a small live region** at the bottom of your terminal. Output you commit, like the final list,
