In this step you turn the counter from the [Quick start](../../../start/quick-start/) into a list of to-do
items that you move through with the arrow keys. The program stays a class with an `update` and a `view`;
what changes is the state it holds.

## What changes

- A new `Item` type: the text of an item, and whether it is done.
- `TodoList` replaces `Counter`. Its state is the list of items and the index of the selected one.
- `view` draws a line per item from that state, and `update` moves the selection.

## The program

Start from the `main.bal` of the Quick start, the counter. If you skipped it, copy the counter's finished
program from [the Quick start](../../../start/quick-start/). You build the list in three stages, and
`bal build` compiles after each. Each stage says whether its code replaces something you already have or is
added to it. The counter's three imports are all still used, so there is nothing to import.

### 1. The item

Add this at the top of the file, below the imports. An item is its text and whether it is done.

```ballerina
type Item record {|
    string text;
    boolean done = false;
|};
```

### 2. The list

Replace the `Counter` class with this one, and replace `main` with the one below it. Do both before you
build, because `main` creates the class by name.

**State is a field.** `items` is the list and `selected` is the index of the highlighted line. `init` takes
the items to start with, so `main` can hand it some. **`view` draws from the state**: a line per item, with a
marker and bold text on the selected one, and a hint line below. `update` is empty for now.

```ballerina
class TodoList {
    *termui:Program;

    Item[] items;
    int selected = 0;

    function init(Item[] items = []) {
        self.items = items;
    }

    public function update(termui:Message message) returns termui:Command? {
        return;
    }

    public function view() returns text:Span[][] {
        text:Span[][] lines = [];
        foreach int i in 0 ..< self.items.length() {
            boolean current = i == self.selected;
            lines.push([
                {text: current ? "> " : "  "},
                {text: self.items[i].text, style: {bold: current}}
            ]);
        }
        lines.push([{text: "up/down move   q quit", style: {dim: true}}]);
        return lines;
    }
}
```

```ballerina
public function main() returns error? {
    termui:Interface ui = new (term:detectEnvironment());
    check ui.run(new TodoList([{text: "buy milk"}, {text: "write the docs"}, {text: "call mum"}]));
}
```

Build it, but do not run it yet: with an empty `update` there is no key that quits.

### 3. Update

**`update` moves the selection.** `up` and `down` change `selected`, and `int:max` and `int:min` keep it
inside the list. `q` quits. Replace the empty `update` with this one:

```ballerina
    public function update(termui:Message message) returns termui:Command? {
        if message is termui:InputEnded {
            return termui:quit();
        }
        if message is term:KeyEvent {
            if message.key == "up" {
                self.selected = int:max(self.selected - 1, 0);
            } else if message.key == "down" {
                self.selected = int:min(self.selected + 1, self.items.length() - 1);
            } else if message.key == "q" {
                return termui:quit();
            }
        }
        return;
    }
```

The first check is for `termui:InputEnded`. When the input ends, in a pipe or a test, the runtime sends it,
and quitting keeps the program from waiting forever. [Headless operation](../../../concepts/headless-modes/)
says more.

Run it:

```sh
bal run
```
