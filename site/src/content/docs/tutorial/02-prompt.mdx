The counter's state was a number. A harness needs a prompt: somewhere to type, edit and resubmit. In
this step the state becomes a `LineEditor`, and a submitted line is **committed** above the prompt, into
your normal scrollback.

## What changed

Starting from step 1, you:

- replace `count` with a `LineEditor` and the terminal width,
- hand it the key and paste events `update` receives,
- commit each submitted line with `commitProse`,
- draw the editor from `view`, and
- quit on Ctrl+C, or when the input ends.

## The program

Start from step 1's complete program, which is on [step 1](../01-counter/). You turn it into the prompt
in four stages, and `bal build` compiles after each one. Each stage says whether its code replaces
something you already have or is added to it. Add imports to the ones at the top of the file, in
alphabetical order.

### 1. A prompt skeleton

Replace the `Counter` class with an empty `Prompt` class. The program no longer counts, so it has no
state yet:

```ballerina
class Prompt {
    *termui:Program;

    public function update(termui:Message message) returns termui:Command? {
        return;
    }

    public function view() returns text:Span[][] {
        return [];
    }
}
```

Replace `main` so it runs the new class:

```ballerina
public function main() returns error? {
    termui:Interface ui = new (term:detectEnvironment());
    check ui.run(new Prompt());
}
```

### 2. State

The editor holds the text and the cursor and remembers what you submit. It owns no terminal. The width
starts at 80; the real one arrives as the program's first message.

Add this import:

```ballerina
import ayesha/termui.input;
```

Replace the `Prompt` class with this one. It adds the editor and the width, and keeps `update` and `view`
empty:

```ballerina
class Prompt {
    *termui:Program;

    private input:LineEditor editor = new;
    private int width = 80;

    public function update(termui:Message message) returns termui:Command? {
        return;
    }

    public function view() returns text:Span[][] {
        return [];
    }
}
```

### 3. Update

**`update` hands events to the editor.** `handleEvent` returns `edited` when it used the event,
`ignored` when it did not, or a `Submitted` with the text when Enter was pressed. The editor is then
empty again.

Inside `Prompt`, replace the empty `update` with this one:

```ballerina
    public function update(termui:Message message) returns termui:Command? {
        if message is term:ResizeEvent {
            self.width = message.width;
            return;
        }
        if message is termui:InputEnded {
            return termui:quit();
        }
        if message is term:KeyEvent|term:PasteEvent {
            input:EditResult result = self.editor.handleEvent(message);
            if result is input:Submitted {
                return termui:commitProse([[{text: "❯ " + result.text, style: {bold: true}}]]);
            }
            if result == "ignored" && message is term:KeyEvent && message.ctrl && message.key == "c" {
                return termui:quit();
            }
        }
        return;
    }
```

Three things worth noticing:

- A submitted line becomes a **command**: `commitProse` writes it above the live region, once. It is not
  state, so the program does not keep it. The terminal's scrollback holds the history of the session.
- Ctrl+C comes back from the editor as `ignored`, because the editor does not use it. That is how a
  program finds the keys that are its own. The editor handles all the editing keys, including Alt+Enter for a new
  line and Ctrl+W to delete a word; see [the line editor](../../concepts/line-editor/) for the full list.
- `termui:InputEnded` arrives when there is no more input, for example in a pipe. Quitting on it means the
  program runs in a script instead of waiting forever. See
  [modes and headless operation](../../concepts/headless-modes/).

### 4. View

**`view` draws the editor.** `render(width, prompt)` wraps long lines by display width, indents later
rows under the prompt, and shows the cursor as the character under it in reverse video.

Inside `Prompt`, replace the empty `view` with this one:

```ballerina
    public function view() returns text:Span[][] {
        return self.editor.render(self.width, "❯ ");
    }
```

Run it with `bal run`, type, press Enter, then press Up.

## Try this

- Start the editor with some history, so that Up recalls an earlier line straight away:
  `new (history = ["help", "quit"])`. Press Up once and you get `quit`.
- Press Alt+Enter to add a line break, type more, then Enter: both lines are committed together. On macOS
  Terminal and iTerm2 the Option key must be set to send Escape sequences first (the line editor page says
  how).
- Create the editor with `multiline = false` for a one-line prompt: Alt+Enter then does nothing, so typing
  `a`, Alt+Enter and `b` submits `ab`.
