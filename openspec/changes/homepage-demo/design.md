# Design

## Context

The homepage (`site/src/content/docs/index.mdx`) uses Starlight's splash template: a hero (title, tagline, two buttons) and four cards. `harness-demo.cast` (92 by 26, 21.4 s) is already served from `site/public/casts/` and shown on the inline-rendering page through `CastPlayer`. `CastPlayer` creates an asciinema player from a script and, without scripts, shows only a link to the cast file; its poster is fixed at one second in and it never plays by itself. See proposal.md for why.

## Goals / Non-Goals

**Goals:**
- A visitor sees a real interaction running beside the introduction on the homepage's first screen, and can read the same interaction as text when scripts are off.
- The homepage keeps its light look: a one-sentence introduction, no new headings or prose.

**Non-Goals:**
- A new recording or example, or a section that explains scrollback and pipes. The cards already do.
- A new player.

## Decisions

**The recording sits beside the introduction, in a hero override.** Starlight's hero places an image in a narrow second column (about a third of the width), where a 92-column terminal would be unreadable. So the site overrides Starlight's `Hero` component (`site/src/components/Hero.astro`, registered in `components`) with a copy of its structure (title, tagline, action buttons) in a grid whose text column is exactly as wide as the one-line tagline and whose recording takes the rest (about 640 px at a 1500 px window). Below 64rem the columns stack, text first, and the tagline may wrap. The override renders `HomeDemo.astro`, which holds the player and its text fallback; the hero is only used by the homepage. Alternatives: the recording under the hero in the page body (rejected after review: it is not beside the text, and the hero's padding pushes it down the page); Starlight's `hero.image.html` (rejected: same narrow column, and the player's script would not be loaded); a CSS-only rearrangement of the hero and page body (rejected: they are separate containers, so it would depend on layout internals).

**It autoplays and loops, with reduced motion respected.** `CastPlayer` takes opt-in `autoplay` and `loop` props. The script starts playback only when `prefers-reduced-motion` is not set; otherwise the reader gets the poster and a play button. The recording has no sound, so autoplay does not surprise anyone with audio. The default for both props is off, so every other page behaves as before.

**The poster is the frame with everything on screen.** `CastPlayer` takes an optional `poster`, defaulting to the old `npt:0:1`. The homepage uses 13 s, found by replaying the cast: streamed answer, committed tool output, the live region and the first approval prompt are all visible. That frame is what readers with reduced motion see.

**The fallback is text in the page, not an image.** `CastPlayer` takes an optional description as a named `fallback` slot (so it can hold a list and preformatted text), shown inside `<noscript>` after the notice and download link. On the homepage it is an ordered walk-through of the recording plus a plain-text copy of the frame at 13 s, generated by replaying the cast through `pyte` rather than retyped. The slot holds a plain `<pre>`, not a fenced code block: Expressive Code emits its base styles with the first code block on a page, and a block inside `<noscript>` would leave later blocks unstyled. Alternative: the GIF as an `<img>`. It is 422 KB, it moves, and alt text cannot carry the content. The text only shows without scripts, so it does not add to the page for most readers.

**The source link is in the caption.** `CastPlayer` renders its caption as HTML so the homepage caption can link to `examples/agent-harness`. The other captions are plain text and are unaffected. The page carries no run instructions: the example's manifest and the Quick start already cover running things.

**One short sentence says "general-purpose".** The hero tagline, the site description and the README tagline all read "A general-purpose terminal UI library for Ballerina." The features that the old tagline listed are on the four cards beside and below it, and the harness is shown as one example by the recording and its caption.

## Risks / Trade-offs

- [Eighty-plus columns shrink to small text on a phone] -> The recording scales to the container: about 12 px text beside the introduction on a desktop, but about 6 px at 390 px wide. The text description and caption still carry the content. A minimum width with sideways scrolling on narrow screens is an option if this matters; it is not part of this change unless asked for.
- [The transcript drifts if the recording is re-recorded] -> `CONTRIBUTING.md`'s line on recordings says to update the homepage description and poster time when `harness-demo.cast` is replaced.
- [Autoplay costs attention and a little CPU] -> The player is already loaded on other pages, the cast is 40 KB, and reduced-motion readers do not get it.
